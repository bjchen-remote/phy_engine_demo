# 引擎性能与结构审查（2026-09-23）

本记录针对公开引擎的求解、场景校验、结果落盘与视频路径。测量工具为
`benchmarks/benchmark_stages.py`；每次使用新的临时运行目录，并将 C 调用、
Python 前后处理、JSON 写入和可选视频编码分别计时。阶段时间存在嵌套，
不可直接全部相加；脚本输出解释每个边界。

## 当前判断

- 粒子 DFSPH、网格 XPBD、连接和混合求解的时间循环均已在 C 中。
  Python 仍负责场景合同、初态、桥接、结果核验与参考求解。
  把整套 Python 参考实现移植到 C 不能自动降低现有主路径的复杂度。
- 混合场景的刚体采样点逐一访问全部网格三角形，复杂度为
  `O(耦合子步 × 接触迭代 × 刚体采样数 × 三角形数)`。
  `core/native/coupled_native.c` 的 `rigid_mesh_sample` 是首选的量级改进位置。
  独立网格求解器已有 BVH，但复用时必须保证变形顶点的位置更新不会漏掉候选面，
  并保持双向冲量、摩擦和接触顺序的数值验收。
- 混合接触还逐粒子扫描全部刚体、点质量和连接；
  粒子求解每子步及每轮接触迭代重建邻居网格。
  空间粗筛和安全余量邻居表值得单独实验，必须用位移上界证明不会漏接触。
- 场景与结果代码的主要维护成本在长函数和重复发布副本。
  `io/schema.py` 的实体规范化、`analysis/results.py` 的质量门、
  `runner.py` 的运行编排宜分阶段提取纯函数；
  `toolboxes/physics/physics_release` 应继续由构建器同步并用 `--check` 校验。

## 本机分段样本

以下是同机单次热缓存、无视频的观测值，不是跨机器性能承诺。

| 场景 | 总时间 | C 求解调用 | 校验 | JSON 写入 | 质量摘要 |
|---|---:|---:|---:|---:|---:|
| `mesh_soft_drop.json` | 0.460 s | 0.179 s | 0.143 s | 0.062 s | 0.047 s |
| `solid_spring_water.json` | 1.726 s | 1.637 s | 0.001 s | 0.054 s | 0.009 s |

两场景的瓶颈不同：小网格案例的几何校验和持久化占比明显，
混合案例几乎由 C 求解决定。三体示例的暖启动 C 调用约 0.0003 s，
此类极短运行的动态库加载和 JSON 成本比积分更大。

## 已落地的低风险改动

粒子自引力 `theta=0` 使用逐对直接求和（严格模式默认选择它）。
它现在只绑定粒子位置，不再为不会被访问的 Barnes–Hut 八叉树分配内存或重建节点。
`theta>0` 仍走原树算法。定向测试核对直接力与独立 Python 算式、
树模式的同场景轨迹及超时语义。微基准只测建树/绑定和引力核：
2 粒子约 2.88 倍、16 粒子约 1.39 倍、64 粒子约 1.08 倍、
256 粒子约 1.01 倍；这些数字不代表整条模拟流水线加速。

## 2026-09-24：接触与邻格优化

混合求解的刚体采样点现在先按**当前三角形顶点**做保守 AABB 粗筛；
真实接触后刷新采样点，仍按原三角形顺序求精确距离、处理冲量并检查超时。
同机 11 次 C 求解中位数：稀疏网格 70.73→31.07 ms（2.28 倍），
近场 71.97→48.43 ms（1.49 倍），全部三角形均为候选的构造场景
210.43→204.22 ms（1.03 倍）。数据与场景参数见
`benchmarks/results/coupled-aabb-macos-2026-09-24.json`；7 个原生场景的
状态与帧输出逐值相等。粗筛降低精确三角形距离计算次数，
最坏渐近复杂度仍是 `O(采样点 × 三角面)`。

原生粒子邻格重建把每个占用哈希格的 27 个邻格槽位缓存一次，
计数和填充两遍复用，邻居顺序不变。格查询从约 `54N` 降至 `27M`
（`N` 为粒子数，`M` 为占用格数）；候选粒子距离计算并未减少，
额外内存约 `88N` 字节。4096 粒子直接重建、同机 ABBA 对照中，
单线程稀疏 1.28→0.59 ms/次（2.17 倍），单线程密集
2.43→2.18 ms/次（1.11 倍）；4 线程密集约 1.18 倍。
水滴短时完整求解的轨迹帧 SHA256 相同，总求解时间的收益约 5%，
存在运行噪声。原始数据见
`benchmarks/results/neighbor-grid-macos-2026-09-24.json`。

## 2026-09-24：网格相交审核

网格 BVH 找到候选面后，精确相交检查会让同一三角形参与多次配对。
现在每次审核按需缓存各三角形的法线、二维投影与投影边长，
复用这些不随候选面变化的几何量。候选遍历顺序、精确测试次数、
相交判定以及工作量和 2 秒时间门保持不变；最坏复杂度仍由
BVH 候选数量决定。

同机预热后交替运行 8 次，仅计 `_intersection_pair`：528 面椭球
0.162→0.128 s（1.27 倍），2208 面椭球 0.685→0.555 s（1.24 倍），
1152 面布片 1.062→0.871 s（1.22 倍）。几何生成、导入与整条模拟
流水线不在这些计时内。复现脚本与原始计时见
`benchmarks/benchmark_mesh_audit.py` 和
`benchmarks/results/mesh-audit-macos-2026-09-24.json`。

## 后续方向

1. 对变形网格试验每子步重拟合的 BVH，在相同接触顺序和超时门下验证候选查询能否由逐面扫描转为 `O(log T + K)`；先测重拟合成本。
2. 继续评估受限 C 几何核对网格审核的收益，同时测量调用与数据转换成本；保持边界接触、相交拒绝和 2 秒审核限制。
3. 按场景族分别比较求解、校验、视频与落盘；性能变化必须同时报告物理参数、误差门和峰值内存。
