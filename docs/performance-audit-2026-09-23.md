# 引擎性能与结构审查（2026-09-23）

本记录针对公开引擎的求解、场景校验、结果落盘与视频路径。测量工具为
`benchmarks/benchmark_stages.py`；每次使用新的临时运行目录，并将 C 调用、
Python 前后处理、JSON 写入和可选视频编码分别计时。阶段时间存在嵌套，
不可直接全部相加；脚本输出解释每个边界。

## 当前判断

- 粒子 DFSPH、网格 XPBD、连接和混合求解的时间循环均已在 C 中。
  Python 仍负责场景合同、初态、桥接、结果核验与参考求解。
  把整套 Python 参考实现移植到 C 不能自动降低现有主路径的复杂度。
- 混合场景的刚体采样点逐一访问全部网格三角形，复杂度为
  `O(耦合子步 × 接触迭代 × 刚体采样数 × 三角形数)`。
  `core/native/coupled_native.c` 的 `rigid_mesh_sample` 是首选的量级改进位置。
  独立网格求解器已有 BVH，但复用时必须保证变形顶点的位置更新不会漏掉候选面，
  并保持双向冲量、摩擦和接触顺序的数值验收。
- 混合接触还逐粒子扫描全部刚体、点质量和连接；
  粒子求解每子步及每轮接触迭代重建邻居网格。
  空间粗筛和安全余量邻居表值得单独实验，必须用位移上界证明不会漏接触。
- 场景与结果代码的主要维护成本在长函数和重复发布副本。
  `io/schema.py` 的实体规范化、`analysis/results.py` 的质量门、
  `runner.py` 的运行编排宜分阶段提取纯函数；
  `toolboxes/physics/physics_release` 应继续由构建器同步并用 `--check` 校验。

## 本机分段样本

以下是同机单次热缓存、无视频的观测值，不是跨机器性能承诺。

| 场景 | 总时间 | C 求解调用 | 校验 | JSON 写入 | 质量摘要 |
|---|---:|---:|---:|---:|---:|
| `mesh_soft_drop.json` | 0.460 s | 0.179 s | 0.143 s | 0.062 s | 0.047 s |
| `solid_spring_water.json` | 1.726 s | 1.637 s | 0.001 s | 0.054 s | 0.009 s |

两场景的瓶颈不同：小网格案例的几何校验和持久化占比明显，
混合案例几乎由 C 求解决定。三体示例的暖启动 C 调用约 0.0003 s，
此类极短运行的动态库加载和 JSON 成本比积分更大。

## 已落地的低风险改动

粒子自引力 `theta=0` 使用逐对直接求和（严格模式默认选择它）。
它现在只绑定粒子位置，不再为不会被访问的 Barnes–Hut 八叉树分配内存或重建节点。
`theta>0` 仍走原树算法。定向测试核对直接力与独立 Python 算式、
树模式的同场景轨迹及超时语义。微基准只测建树/绑定和引力核：
2 粒子约 2.88 倍、16 粒子约 1.39 倍、64 粒子约 1.08 倍、
256 粒子约 1.01 倍；这些数字不代表整条模拟流水线加速。

## 下一轮验证顺序

1. 为刚体–网格接触记录三角面数、候选数、接触阶段耗时，构造稀疏与密集网格对照。
2. 实现可更新且保守的候选面查询，再用静态、软体、摩擦和动量回归对照原实现。
3. 单独评估粒子邻居网格重建的次数和耗时；只有位移边界成立才缓存候选。
4. 按场景族分别比较求解、校验、视频与落盘，性能变化同时报告物理参数与误差门。
