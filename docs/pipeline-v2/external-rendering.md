# 商用生成式渲染扩展与高精模块门禁

状态核验：2026-09-26。本文是后续实施设计；未配置商用账号、未读取凭据、未上传用户产物、未调用付费生成服务。与 [实施规划](implementation-plan.md) 配合阅读；其中“通过宿主 broker 配置”描述的是目标架构，当前代码没有 broker。

## 当前实现与后续范围

| 能力 | 当前状态 | 具体边界 |
| --- | --- | --- |
| 本地科学视频与数据包 | 已实现 | `render_simulation`、`export_data` 读取保存结果，产生 H.264 MP4 与 JSON/CSV ZIP；原始结果 hash 在处理后复核。 |
| `standard` / `preview` | 已实现 | 现有科学渲染器、录制状态插值、独立渲染预算；不改变数值精度。 |
| 外部请求与回执格式 | 已实现纯函数 | [providers.py](../../toolboxes/pipeline_presentation/providers.py) 创建请求摘要，校验回执绑定、所报费用及媒体描述，并固定 `illustrative_only` 和 `measurement_source=false`。 |
| 外部鉴权、网络与任务恢复 | 待实现 | 没有凭据 broker、上传器、HTTP adapter、持久任务账本、轮询器或取消器。 |
| 计费上限执行 | 待实现 | 当前 `max_cost_usd` 只是契约字段及回执检查，没有预算预留、扣费授权或账单对账。 |
| 下载与真实性验证 | 待实现 | 当前回执函数不下载文件、不核验文件实际 hash、不解码商用输出，也不证明费用来自真实服务。 |
| `high` CAD / `deep` PBR | 待实现 | 当前 capability 不开放；不能把普通网格或插值视频标记为已实现高精建模、深度渲染。 |
| 同时投递科学视频、艺术视频、数据包 | 待实现 | 当前兼容外层保留唯一 MP4 和最多一个 ZIP 附件；额外艺术视频需要正式扩展产物角色与逐件 outbox，不能偷偷替换科学视频。 |

`provider_request(upload_allowed=True, ...)` 的布尔值不能替代真实用户/部署授权。普通 SHA-256 也不是签名或访问凭证。后续 broker 必须从宿主可信的授权记录读取权限，不能相信弱 agent 或第三方回执自行声明已经获准。

## 一手来源核验：Runway

Runway 可作为首个商用视频编辑 adapter 的候选。官方更新记录显示，当前 `aleph2` 支持用提示词编辑既有视频，通过 video-to-video 接口接入；旧 `gen4_aleph` 已停止提供。应把 provider、模型标识、API 版本与 adapter 内容摘要写入任务 lock，避免服务升级后静默改变任务目标。[Runway API 更新记录](https://docs.dev.runwayml.com/api-details/api_changelog/)

相关事实与本项目的设计推论分开记录：

| 官方当前文档事实 | 对本项目的设计要求 |
| --- | --- |
| Aleph 2.0 输入为 2–30 秒、最高 1080p、帧率不超过 30；支持 H.264 MP4。 | 现有本地科学视频可作为候选输入；提交前用解码后的真实尺寸、时长、帧率校验，超限时产生单独的参考副本及变换清单。 |
| 视频经 URL、data URI、临时上传的大小限制不同；URL 需要 HTTPS 域名、正确响应头和 HEAD 支持，且不跟随重定向。 | adapter 选择一种经测试的上传方式，按该方式验收字节限制；不用本机路径或 NAS 地址冒充公网素材地址。 |
| 临时上传得到的 `runway://` 资源引用有使用期限。 | 上传引用及到期时间属于 broker 状态，不能成为永久交付地址。 |

这些媒体限制来自 [Runway 输入文档](https://docs.dev.runwayml.com/assets/inputs/)，上线时重新核验并将参数快照写入 adapter 测试夹具；表内兼容判断属于本项目推论，不代表已完成云端试跑。

生成接口返回任务 ID，可再查询任务。官方明确说明等待超时或中止等待不会自动取消服务端任务，取消需另行调用取消接口。[Runway SDK 任务说明](https://docs.dev.runwayml.com/api-details/sdks/)

Python SDK 默认会对连接错误、部分 HTTP 状态和超时重试；可用 `max_retries=0` 禁用。首版 adapter 的创建任务调用应关闭隐藏重试，由持久账本统一决定是否重试。[Runway 官方 Python SDK](https://github.com/runwayml/sdk-python#retries)

本次查阅的公开说明没有为所选创建任务路径确认服务端幂等键保障。因此不能把内部 `request_sha256` 当成 Runway 的幂等协议；这是当前核验的边界，并非断言其所有服务均不支持幂等。

成功任务的输出链接会过期，官方要求下载到自己的存储，不能直接作为产品永久链接。[Runway 输出文档](https://docs.dev.runwayml.com/assets/outputs/)

## 目标数据流与职责

```text
固定的 simulation result + 模型/观测/质量状态
  ├─ 本地科学渲染 → scientific-video + data.zip → QQ 独立回执
  └─ 只读 reference-video 副本
       → 宿主授权及预算预留 → 外网/凭据 broker → 固定 provider adapter
       → 下载、解码、费用对账 → illustrative-video → 新增的独立投递回执
```

阶段 toolbox 继续保持无网络、无商用凭据。它只能提交绑定当前 task、bundle lock 与源产物 hash 的意向；broker 负责授权、凭据、外网、付费和异步恢复。弱 agent 仅看到 capability、估价、任务状态与已经验证的产物描述，不能拿到 API 密钥或执行任意 URL 请求。

broker 的未来实现边界：

1. 凭据由部署时接入系统密钥存储，运行时仅在 broker 进程内使用；任务 JSON、内容寻址包、ZIP、提示词和日志都不携带密钥。授权记录包含 provider、资产范围、预算上限和授权有效范围，已获准范围内的恢复不重复索求授权。
2. 出站 API 目的地与操作由版本化 adapter 白名单决定。临时上传签名链接、结果下载域名需由受信任 API 响应和显式规则验证；不接受 agent 指定任意主机，也不转发 QQ/NAS 的凭据。
3. 首版只上传已核对 hash 的科学参考视频。`result.json`、CSV、模型文件、QQ 对话、用户身份和本机目录均不属于默认上传范围。提示词来自当前渲染要求，不能自动附带这些上下文。将来若需要关键帧或法线图，升级资产范围与请求契约后再启用。
4. 原始上传文件、实际请求参数和输出分别记摘要；参考副本如果经过缩放、裁切、片段选择或时长变换，记录变换及原文件关系。引用的摘要与被上传的实际字节必须一致。
5. 用已有稳定科学结果完成默认交付；外部增强失败时保留该结果，明确报告增强失败或状态未知。不能为了外部渲染失败重跑求解器。

## 幂等、未知状态与恢复

建议持久任务键为 `(QQ task_id, render_revision, provider_adapter_digest, request_sha256)`。唯一约束在网络提交之前生效；更新提示词、模型或参考视频则产生新 revision，并重新核算预算。`request_sha256` 负责内容绑定，数据库唯一约束负责本地去重，二者都不能保证远端恰好执行一次。

| 状态/事件 | 持久动作 | 是否再次创建付费任务 |
| --- | --- | --- |
| `planned` → `reserved` | 核对能力、输入 hash、授权与价格快照；事务预留额度。 | 尚未提交。 |
| `reserved` → `submitting` | 先落盘 attempt_id、请求摘要、预留额度，再发一次创建请求。 | 一次。 |
| 收到 provider task ID | 原子保存 ID，进入 `accepted`；后续查询此 ID。 | 否。 |
| 提交超时、连接中断、崩溃，无法确认远端是否接受 | 进入 `submission_unknown`，保留额度及证据；恢复只对账/核实。 | 默认否；不能因为本地没有 ID 自动重发。 |
| 已知 ID 的轮询超时 | 进入 `polling_deferred`，保存下一次查询时间，退避恢复 GET。 | 否。 |
| 服务端排队或 `THROTTLED` | 保留 ID、额度和等待状态。 | 否。 |
| 用户取消或本地截止时间到达 | 有 ID 时发取消请求并记录 `cancel_pending`；无确定回执保持未知。 | 否；不能声称已经停止或退款。 |
| 服务端成功 | 下载到隔离临时目录，校验后进入 `artifact_verified`；随后费用对账。 | 否。 |
| 明确拒绝且确认没有创建/收费 | 保存终态，按限额及退避策略创建新 attempt。 | 只有已确认可安全重试时。 |

Runway 的并发超额可能成为服务端 `THROTTLED` 排队，日配额限制也可能返回 429；本项目不能把“未开始处理”误当成“未创建”。[Runway 使用限额](https://docs.dev.runwayml.com/usage/tiers/)

“提交被接受、响应丢失”的测试必须覆盖重启恢复。若 provider 没有可核验的幂等或任务检索能力，`submission_unknown` 只能等待对账或让用户明确决定是否承担重复生成/收费风险。不能以“恰好一次”包装这一限制。

## 费用预算与回执

Runway 使用 credits 计价。当前价格页面将一 credit 标为 0.01 美元，Aleph 2.0 标为每秒 28 credits、每次至少 56 credits；价格、附加输出格式和税费均需在真正接入时重新核验。这只是本次查询的估价依据，没有发生购买或扣款。[Runway 官方定价](https://docs.dev.runwayml.com/guides/pricing/)

未来 broker 采用整数微美元/credits 账本，避免以浮点误差决定费用授权。每次提交固定模型、时长、分辨率、输出格式和计费版本，按可证明的最坏费用预留；除了当前请求上限，还同时检查用户/任务/部署级累计额度。未结算的 unknown 任务继续占用额度，不能靠重试绕开总上限。若 provider 不能给出可执行的费用上界，该组合保持不可用。

当前 `max_cost_usd` 字段应解释为生成服务费用上限；未来还需分别定义税费、资产存储和下载费用是否包括在总预算中，不能临时扩大口径。服务端取消不等于零费用或退款，只有账单或可核验的服务回执才能调整已用额度。

不能把预估费用、缺失费用或未知费用填成 `cost_usd=0` 来通过当前 `validate_provider_receipt`。未来契约增加 `estimated`、`reserved`、`actual`、`unknown` 的费用状态；媒体成功与费用结算分别持久化。当前纯函数只验证已经提供的数值，不具备计费真实性验证能力。

## 产物验证、数据解释与 QQ 投递

科学数据始终来自固定 simulator 的 canonical result/observations；商业模型输出不回写这些文件。提交前后与下载后复核源摘要，校验失败时停止发布增强产物。生成式视频不能用于反推位移、温度、应力、事件时间或补齐未保存的观测；即便画面肉眼一致，`measurement_source` 仍为 `false`。

外部完成后，broker 下载输出并检查实际媒体类型、大小、时长、帧数、完整解码及 SHA-256。失败只保留失败记录，不能仅凭 URL 或 provider 的“成功”状态宣称已交付。临时外网链接不出现在 QQ 永久回执；重发复用本地验证过的文件，不再次付费生成。

未来 `illustrative-video` manifest 至少增加：provider task ID、adapter/模型/API 版本、请求摘要、科学参考视频摘要、原始 result 摘要、实际输出摘要、解码记录、费用状态，以及固定的 `generative=true`、`fidelity=illustrative_only`、`measurement_source=false`。可见标题/片头及 QQ 文案均说明“AI 风格化演示；定量数据以科学模拟数据包为准”。原始结果未过数值验收时，艺术视频不能把质量状态升级为已通过。

当前协议不能同时把两个 MP4 放进唯一视频槽。先扩展为带明确 `role` 的产物列表，并为科学视频、艺术视频、数据 ZIP 分别持久投递回执和清理引用，再开放在线 provider。该扩展需要宿主 capability 协商和旧版本拒绝/兼容测试；不属于本轮已经完成的本地渲染能力。

## `high` CAD 与 `deep` PBR 的开放条件

这两个选项独立于 `simulation_quality=strict`；商用 diffusion 也不能替代下面的门禁。

| 模块 | 对外开放前必须补齐 | 不得据此声称的能力 |
| --- | --- | --- |
| 高精 CAD/网格建模 | 可重复的几何资产导入/生成；单位、坐标系和来源；尺寸公差与拟合误差；拓扑/法向/封闭性检查；质量、惯量与碰撞代理的映射；导出格式兼容；失败样本回归。建模包与资产内容摘要进入组合 lock。 | 网格更密不等于新增物理定律。1.4.0 不支持的材料、接触或连续介质求解仍要明确返回不支持。 |
| 深度 PBR/离线路径追踪 | 明确可调用且版本锁定的渲染器；实体 ID、变形网格、刚体姿态、相机和物理时间映射；材质/灯光不改变几何；可复用缓存；GPU/时长/字节预算；完整解码；参考场景的几何、遮挡、轨迹和数值色标比对。 | 材质、阴影、景深与高采样只改展示，不能提高模拟精度。生成纹理或环境图需有独立来源/使用范围。 |
| 商用 diffusion 演示 | 可信 broker、上传/费用授权、持久幂等状态、未知状态对账、真实下载验证、显式艺术标签、独立 QQ 回执。 | 输出不是高精几何、守恒证明、求解采样或 PBR 保真认证。 |

初次模块启用先用本地固定输入进行契约、重启、超时、源 hash 不变和降级回归；商用联网测试使用单独的有限测试额度。全部门禁通过后才在 `pipeline_capabilities` 公布相应能力，并用新的组合 digest 原子激活。没有通过时继续提供已验证的 `standard` / `preview` 与原始数据。

## 后续实施顺序与验收

1. 实现 broker 的本地账本与模拟 provider：覆盖提交响应丢失、并发重复请求、进程重启、费用未知、取消状态未知，确保不会自动重复付费。此阶段不联网。
2. 扩展 manifest 与 QQ 逐产物 outbox，验证三件产物的部分成功、未知回执、恢复投递及保留行为；当前兼容模式继续只发科学视频和 ZIP。
3. 固定一个 Runway adapter 和输入规范，接入部署凭据存储、出站白名单、资产上传/下载和真实费用对账；在线测试须有明确上传范围与测试额度。
4. 分别建设高精建模与 PBR 模块，完成表中几何与视觉门禁。每个模块可独立发布新版本，但任务仍 pin 完整组合，旧任务保持原版本。

验收记录需分别写明“本地契约测试通过”“真实 provider 调用验证通过”“QQ 平台投递回执确认”，不能用前一项替代后一项。
