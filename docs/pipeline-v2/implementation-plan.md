# QQ 可部署兼容方案与实施门禁

2026-09-26；本文件补充原 v2 草案，记录本轮实施范围和架构修正。最终完成情况以 implementation-report.md 为准。

现有 QQ 已经具备单 toolbox 的内容寻址发布、原子 active 切换和任务 pin；它尚未支持三模块独立更新后的组合一致性，也不能发送正式数据文件。仅新增三个 API 名称不能达成热插拔。

## 可直接承接 1.4.0 的方案

保留 1.4.0 的机械/PCB 求解器与现有 `physics_prepare / physics_simulate` 调用，增加一个可发布的组合 toolbox。组合包内包含固定引擎快照，以及独立建模、模拟、渲染模块；`bundle-lock.json` 逐项记录版本和内容摘要。每阶段以固定参数启动独立 Python 进程，不能将新旧模块混入同一导入缓存。

模块可单独换版本，组合构建器验证接口、复制完整依赖并生成新包。QQ 继续原子激活一个组合 digest，所以任务接收时一次 pin 就固定全部依赖。运行中任务、失败恢复与回滚继承现有机制。新的组合仍使用 v1 外层协议；原设计中的通用异步 v2 API 留作后续演进，不伪装成已实现。

实际热插拔步骤为：构建指定模块组合 → 本地验收 → 发布新内容摘要 → 原子激活。新任务读取新包；旧任务引用旧包。没有自动删除旧包的命令，因此不会提前回收运行中依赖；持久引用计数 GC 另行实现。

## 数据与视觉

模拟阶段正式采用已有 `make_video=False` 路径，完成后封存规范模型、数值结果、观测、诊断及其 hash。渲染阶段读取保存的数据；重渲染不得调用求解器或改动 canonical 文件。数据包提供 JSON、带单位的 CSV、数据字典及内部 manifest，区分求解步观测与抽样显示帧。

QQ 输出继续保留唯一 MP4 的 outputs；另加最多一个受验证的数据 ZIP attachment。宿主一次性排队视频和数据，分别保存回执；数据状态未知时不重复发送、不宣称全部交付，也不因视频先完成而清理数据。文件能力需要宿主一次性升级并显式启用，之后切换建模/模拟/渲染组合不需要重启客户端。

展示侧先利用已存在的本地科学渲染、完整时间慢动作和预算编码。可选生成式 provider 必须将结果声明为 illustrative，原视频和数值数据保留。商用 diffusion 的凭据、上传与成本通过独立宿主 broker 配置，当前无凭据时仍能完整运行本地流程；不为“deep”名称自动调用无预算付费服务。

高精建模、严格数值验证、深度渲染继续独立。首批只公布真实可验收档位；没有几何容差验证或对应渲染 provider 时返回明确 unsupported，不能把普通输出标记成 high/deep。

## 本轮实现顺序

1. 固定并核验本机已有 1.4.0 快照，作为兼容集成测试的真实引擎输入；同时保持当前 1.4.2 工作区和活动版本独立。
2. 实现独立阶段、组合构建器、版本锁与阶段产物校验；以现有 agent API 完成建模和执行。
3. 实现数据 ZIP 与 QQ 群文件 outbox/transport、独立回执及保留规则，旧单视频任务保持兼容。
4. 完成真实机械/PCB 输出、独立重渲染与输入 hash 不变测试，完成模块更换/原任务固定版本回归。
5. 更新三份运行技能、使用文档和实际实现报告；把商用视觉增强的接缝与未配置项明确列出。

本机离线验收不等于 QQ 平台端到端验收。若没有真实用户请求及平台回执，不声称群文件已送到 QQ；不发送测试群消息，也不改变群、账号和第三方客户端安装状态。
